# Этап 2. Классификация

**Сделано**
- `src/pipeline/classify.ts`: тип по заголовку (contract / amendment / draft / letter / unknown), номер документа, номер договора из текста по шаблону `config.contractNo`, статус подписания по строке «Статус:», даты документа, подписания, вступления в силу.
- Каждое решение пишется в трассу с `rule_id`, номером строки и цитатой.
- `needs_review` с причиной: тип не распознан, номер договора не найден, упомянуто несколько договоров, противоречивый статус («проект» и «подписано»), проект со статусом «подписан», у договора/ДС нет статуса, подписанное ДС без даты вступления в силу.
- Все словари — в `src/config.ts`.

**Решения**
- `\b` в JS не работает с кириллицей — используем `(?!\p{L})`.
- Для писем и проектов отсутствие строки статуса — норма, `needs_review` не ставится: они в любом случае не меняют условия.

**Как проверить**
`npm test` — тест сверяет классификацию всех 6 файлов и то, что перестановка имён и обратный порядок загрузки дают тот же результат.
