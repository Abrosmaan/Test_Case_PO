# Тест-кейсы Contract Checker

80 документов (позитивных — 39, негативных — 41). Дата проверки по умолчанию — 10.03.2026. Эталон из задания — в `Test Files/`, здесь расширенный набор.

## Как пользоваться

- Все 80 файлов лежат в одной папке `cases/` — грузить одной пачкой. Номера договоров между сценариями не пересекаются, ожидания верны и для общей загрузки.
- Префикс имени — группа сценария: `01` форматы, `02a`…`02l` допсоглашения, `03` ловушки, `04` приём файлов, `05` содержание, `06` опечатки. Файлы одного сценария допсоглашений имеют общий префикс (`02a_…`).
- Эталон из `Test Files/` грузить отдельно: в нём ДС №1 к STN-101, и вместе с `04_dup_*` он изменит ожидания по STN-101 (1 380 000 ₽, 30.04.2026).
- `expected.json` — машиночитаемые ожидания: по каждому файлу (`ingest`, `doc_type`, `contract_no`, `sign_status`), по каждому договору (`amount`, `delivery_date`, источник, предложения) и `must_not_appear` — номера, которых не должно быть в таблице.
- `needs_review` — допустим статус «требует проверки». Недопустимо выдать конкретное число или дату молча.
- Набор собирается `gen.py` (Python 3, `python-docx`, `reportlab`, `openpyxl`): `python3 "Test Cases/gen.py" "Test Cases/cases" "Test Files"` из корня проекта. Текстовые файлы воспроизводятся байт в байт; в DOCX/PDF/XLSX/ZIP при пересборке меняются только внутренние метки времени.
