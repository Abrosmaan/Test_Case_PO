# Edge-кейсы: расторжение, нераспознанные ДС, заметки, промпт-инъекции

Перед доработкой прогнал 10 edge-кейсов через настоящий конвейер. Три давали **молча неверный** результат — хуже, чем «нет данных».

| Кейс | Было | Стало |
|---|---|---|
| Подписанное ДС о расторжении | договор «действует», ДС «применено», ничего не изменило | «расторгнут с ДАТА», исключён из «поставки раньше даты»; будущая дата → «расторгается с …» |
| ДС меняет срок без «изложить в редакции» | старый срок «действует» | поле и договор «требует проверки» с цитатой пункта |
| ДС излагает п. 2.1 без суммы | старая сумма «действует» | сумма «требует проверки» |
| Поэтапная поставка (2 даты в пункте) | взята первая дата, вторая отброшена | «01.04.2026 / 01.06.2026», «требует проверки» |
| Письмо без значения | невидимо в таблице | 📝 заметка у договора |
| Нераспознанный документ со ссылкой на договор | тихо прикреплялся к договору | договор «требует проверки», документ виден в заметках |
| Промпт-инъекция в документе | модель выполняла её | явные инструкции отсекаются до вызова; промпт с маркерами; результат LLM по-прежнему не меняет таблицу |

**Реализация**
- `src/extractors/termination.ts` — расторжение как событие (факт `termination`), ищется во всех абзацах ДС, проектов и писем.
- `src/pipeline/resolve.ts` — у применённого ДС каждый пронумерованный пункт должен быть либо новой редакцией, либо расторжением, либо стандартной фразой («без изменений», «вступает в силу»). Иначе — «нераспознанное изменение»: договор и затронутые поля (по словарю `fieldHints` в `src/config.ts`) получают «требует проверки». Значение остаётся видно, но уже не выдаётся за достоверное.
- `delivery_date`: в пункте со сроком поставки учитываются все «не позднее ДАТА».
- Заметки: связанные с договором письма, проекты и неприменённые ДС, которые не дали предложений.
- `src/llm/classify.ts` — `findInjection()` и промпт со случайными маркерами; `src/llm/fallback.ts` — подозрительный документ получает `llm_status = suspected`, LLM не вызывается.
- UI: метка расторжения, колонка «Статус» с флагами и карточкой договора по клику, заметки в карточке и рядом со значением, легенда.

**Живая проверка инъекций (qwen3:8b)**: явная инъекция отсечена до вызова; «вежливая» без ключевых слов модель выполнила, после добавления признака «классифицировать» — отсекается. Перефразированная может пройти, поэтому главная защита — архитектурная: ответ LLM не меняет таблицу.

**Не решено**
- Даты прописью, «тыс. руб.», многострочные пункты → «нет данных».
- Два ДС с одной датой вступления, меняющие один пункт, не подсвечиваются как конфликт.
- Номер договора в формате вроде `№ 45/2026-П` не находится в письмах.
- Отдельной сущности «договор» в БД нет: статус расторжения вычисляется на дату проверки, а не хранится.
