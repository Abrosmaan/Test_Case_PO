# Проверка сценария встречи: новое поле `penalty_rate`

**Сделано**
- `src/extractors/penalty_rate.ts`: пункт со словом «неустойка» или «пеня» → первая ставка в %, которая не является лимитом «не более N%». Отмечается «в день» и лимит. Есть «неустойка», но нет % → `no_data` с цитатой («Ставка неустойки в тексте договора не установлена»).
- Регистрация: одна строка в `src/extractors/index.ts`, имя поля в `FieldName`, словари в `src/config.ts`.
- Колонки UI теперь берутся из реестра экстракторов через `GET /api/config`: новое поле не требует правки вёрстки.

**Найдено по ходу**
- Документы в `data/app.db`, загруженные до появления экстрактора, не имели фактов нового поля. Повторная загрузка считалась дублем, и в UI было бы «нет данных». Теперь при старте сервера сохранённые документы переобрабатываются (`reprocessAll`), результат детерминирован.

**Тесты** (`tests/penalty.test.ts`): значения по 3 договорам; «размер неустойки без изменений» в ДС №1 ничего не меняет; лимит перед ставкой не берётся как ставка; подписанное ДС с новой редакцией п. 4.1 меняет ставку («изменено ДС №3»); мутация ставки в договоре меняет результат; переобработка подтягивает новое поле.
