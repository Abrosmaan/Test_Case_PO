# LLM в фоне и без лишних вызовов

**Зачем.** Загрузка 80 файлов ждала ответа LLM на каждый нераспознанный документ (до ~11 с на документ при невалидных ответах), UI просто крутил индикатор.

**Сделано**
- `src/llm/queue.ts` — фоновая очередь: загрузка помечает нераспознанные документы `llm_status = 'pending'` и сразу отвечает (`llm_pending` в ответе). Один обработчик разбирает документы по одному; загрузка во время работы подхватывается сразу после. Перед записью результата проверяется, что документ ещё существует — «Удалить все» во время проверки ничего не ломает.
- `GET /api/llm/status` → `{ enabled, pending, running }`. UI показывает «LLM проверяет…» у документа и «LLM проверяет N документов — таблица обновится сама» в итоге загрузки, опрашивает статус раз в 1,5 с и обновляет таблицу по мере ответов. После перезапуска страницы ожидание продолжается.
- Без LLM поведение прежнее: документы сразу получают «LLM не настроен».

**Лишние вызовы, найденные по вопросу пользователя, и исправления**
1. Каждый перезапуск сервера (в dev — при каждом изменении кода) заново отправлял все нераспознанные документы в модель: повторная обработка при старте сбрасывала её ответы. То же при «Удалить все» и повторной загрузке. → `llm_cache (sha256, model_key, outcome, answer)`, ключ — провайдер/модель/версия промпта. Кешируются валидные ответы и невалидные вердикты модели; сетевые ошибки и таймауты — нет.
2. На невалидный ответ было 3 повтора, а при temperature 0 модель отвечает так же (в логе — 4 одинаковых ответа, ~11 с). → `invalidRetries: 1`; на сетевые ошибки по-прежнему 3 повтора.

**Проверка**
- `tests/llm-queue.test.ts` (модель, отвечающая по команде теста): загрузка возвращается до ответа модели; вторая загрузка во время работы обрабатывается; «Удалить все» во время проверки; распознанные документы не ждут; без LLM.
- `tests/llm.test.ts`: эталонные документы в LLM не уходят; тот же текст после перезапуска, повторной обработки и «Удалить все» — 0 новых вызовов; невалидные ответы — 2 вызова и кеш; сетевые ошибки не кешируются; другая модель спрашивается заново.
- Вживую (qwen3:8b): загрузка 2 нераспознанных документов вернулась за 88 мс, метки «LLM проверяет…», через ~6 с таблица обновилась сама. Перезапуск сервера: 0 новых вызовов, 2 попадания в кеш.
