# e2e-тесты (Playwright)

До этого шага UI проверялся только руками: автотесты покрывали конвейер и API, но не браузер.

**Сделано**
- `e2e/journey.spec.ts` — 12 сценариев через настоящие UI, сервер и SQLite:
  пустое состояние с тремя шагами; пакетная загрузка с PDF, пустым TXT и DOCX (причины отказа, итог, раскрытые подробности), повторная загрузка → дубль; drag & drop; таблица против эталона §5; клик по значению → подсветка цитаты, цепочка изменений, источник предложения, закрытие панели; «нет данных» с причиной; 4 эталонных вопроса; дата проверки 28.02.2026 → исходные значения; расторжение (статус, исключение из «поставок раньше даты», карточка договора, «расторгается с» до даты); письмо без значений → заметка; трасса с отброшенными кандидатами; «Удалить все» → пустое состояние.
- `playwright.config.ts`: свои порты (API 3101, UI 5174), отдельная база `data/e2e.db`, LLM выключена (`LLM_PROVIDER=none` важнее `.env`), один воркер. Рабочую базу и dev-сервер тесты не трогают.
- `npm run test:e2e`; `E2E_SERVER_LOG=1` выводит логи сервера.

**Найдено по ходу**
- Playwright вычисляет конфиг заново в каждом рабочем процессе. Удаление файла базы из конфига выдёргивало её из-под работающего сервера → «attempt to write a readonly database» → 500 на загрузке. Очистка базы перенесена в команду запуска сервера.

**Проверка, что тесты ловят регрессии**: подсветка цитаты временно заменена `<mark>` → `<span>` — упали 2 сценария; после возврата — 12/12.

## Баг: «Внутренняя ошибка» при загрузке пачки (найден пользователем на 80 файлах)

- Причина — не количество файлов, а один файл больше 1 МБ в пачке. `@fastify/multipart` при превышении `fileSize` выбрасывал ошибку на весь запрос (перехват у `toBuffer()` не помогал: плагин повторно выбрасывает её из итератора). В итоге вся пачка терялась с 500.
- Исправление: `throwFileSizeLimit: false` — файл обрезается на лимите + 1 байт, этап приёма отклоняет его как «Файл больше 1024 КБ», остальные файлы обрабатываются. Лимит количества файлов вынесен в `config.upload.maxFiles` (500); превышение → 413 «разбейте загрузку на части». Прочие ошибки клиента → свой статус и читаемый текст вместо «Внутренней ошибки».
- Тесты: `tests/upload.test.ts` (80 файлов с одним на 2 МБ → 79 приняты; несколько больших подряд; 501 файл → 413), e2e-сценарий пакетной загрузки теперь включает файл на 2 МБ.
- Логи e2e-сервера пишутся в `logs/e2e.jsonl` (`LOG_FILE`), не смешиваются с рабочими.
